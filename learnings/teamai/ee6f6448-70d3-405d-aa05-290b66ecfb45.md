For the `teamai` Logical Project, an optional `kind: project` package is a Marketplace source, not an installed or enabled Copilot Plugin. The CLI projects its declared compatible components into owned native paths in a bound Workspace. Keep source selection, component delivery, configuration, and observed consumer loading as separate facts. A binding or delivered file alone does not prove runtime loading; record the named consumer, version, session, and observation. A Logical Project ID identifies business context, not an access-control boundary.

Preserve these diagnostic identifiers and original messages exactly:
- `USER_OVERRIDE`: `Unowned plugin state preserved.`
- `RUNTIME_NOT_OBSERVED`: `Runtime loading was not inspected.`

Source: [V4 Spec #14, F03/F05 and runtime evidence decisions](https://github.com/teamai-vault/teamai-cli-copilot/issues/14).
