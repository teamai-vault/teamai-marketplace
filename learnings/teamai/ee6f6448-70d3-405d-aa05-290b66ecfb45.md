For the `teamai` Logical Project, keep package delivery, configured activation, and runtime observation as separate facts. A Workspace setting marked `true` does not prove that an optional project Plugin package was delivered; a delivered package or selected binding does not prove that a particular Copilot consumer loaded it. Record runtime evidence only for a named consumer, version, and session with an actual observation. A Logical Project ID identifies business context; it is not an access-control boundary.

Preserve these diagnostic identifiers and original messages exactly:
- `USER_OVERRIDE`: `Unowned plugin state preserved.`
- `RUNTIME_NOT_OBSERVED`: `Runtime loading was not inspected.`

Source: [V4 Spec #14, F03/F05 and runtime evidence decisions](https://github.com/teamai-vault/teamai-cli-copilot/issues/14).
