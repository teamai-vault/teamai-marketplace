# Agents Map Probes

Read the sections matching the ecosystems you detected. These are **search prompts** — where evidence might live, never what the repository does. Repository evidence always outranks probe expectations.

## Java / JVM

Build identity:

- `mvnw`, `.mvn/`, `pom.xml`, parent POMs and modules;
- `gradlew`, `settings.gradle*`, `build.gradle*`, version catalogs;
- Java toolchains, `.java-version`, `.tool-versions`;
- company parent POMs/plugins/internal repositories;
- CI invocations and Maven/Gradle profiles.

Verify rather than assume:

- canonical wrapper/build entry point;
- multi-module boundaries;
- Java version actually enforced;
- Surefire vs Failsafe;
- module-focused test strategy (`-pl`, `-am`) if repo-owned workflows use it;
- Checkstyle, Spotless, PMD, SpotBugs, JaCoCo;
- custom Gradle suites/tasks;
- Docker/Testcontainers/service prerequisites.

Trace actual runtime code rather than assuming Controller → Service → Repository:

```text
entry point
→ validation/auth
→ facade/use-case/service
→ domain
→ transaction boundary
→ repository/mapper/client
→ response/event
```

Inspect JPA/Hibernate, MyBatis, JDBC, Feign, WebClient, RestTemplate, MapStruct, Bean Validation, exception mapping, retry/idempotency, messaging, and Spring profiles only when evidence points there.

Distinguish unit, slice, `@SpringBootTest`, contract, Testcontainers, and environment-dependent integration tests.

## JavaScript / TypeScript

Determine the canonical package manager from the lockfile, workspace boundaries (`workspaces`, Turborepo, Nx), the focused test/lint/typecheck scripts as opposed to the full `package.json` list, `tsconfig*` project references, and generated code. Dependency presence alone is not evidence of active architecture.

## Python

Determine the canonical environment/package manager (`pyproject.toml` plus lockfile, tox/nox), how tests are selected and which markers gate integration prerequisites, lint/type configuration actually enforced in CI, and real entry points (console scripts, ASGI/WSGI startup).

## Go

Determine module/workspace layout, the binaries under `cmd/`, build tags and test flags that gate integration suites, generated files and their generator, and the task runner CI actually invokes.

Trace a real `cmd/main → server/worker → handler → service/domain → boundary` path.

## Rust

Determine workspace members, binaries/examples, `rust-toolchain*`, clippy/fmt/test invocation, and code generated by build scripts. An optional Cargo feature is not active behavior without evidence.

## .NET

Determine solution/project layout, the SDK pinned by `global.json`, central package management, test projects, analyzers/formatters, ASP.NET entry points, and EF migrations.

## Monorepo

Regardless of language: the workspace/package graph, package-local instructions, the working directory each command expects, shared tooling versus applications, independently deployable units, and per-package CI. Use nested `AGENTS.md` only when scope-specific behavior materially differs.
